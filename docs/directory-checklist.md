# Directory checklist for plugins/combat-writing

A pass over the Claude plugin directory's pre-submission checklist (claude.com/docs/plugins/pre-submission-checklist) and the submit page (claude.com/docs/plugins/submit), item by item, against `plugins/combat-writing/`. The plugin folder is a subfolder of the repository; the directory reads and scans only that folder.

**Re-passed 2026-11-21**, against the checklist as it read that day. This is the page's one date: it moves only when the whole pass is re-run against the repository, row by row, never when one row changes. No row carries a number a test measures (a file count, a file size, a version, a date of measurement): each row names the test or the file that holds the item, and the number lives there. The plugin's version is in `plugins/combat-writing/.claude-plugin/plugin.json`; the record of every part is `PLAN.md` from Part 91 on, with Parts 1 to 90 frozen in `PLAN_ARCHIVE.md`.

Two kinds of check exist, and this page keeps them apart:

- **Checked here:** verified in this repository with `claude plugin validate --strict` and `tests/*_check.js`, which CI runs on every pull request, and by `node tests/run_all.js`, which runs the same set in one command.
- **Portal only:** the developer portal's **Validate** button at claude.ai/directory/manage runs the directory's own checks (name taken, look-alike names, the security scan). That button is the founder's step. Nothing in this repository can run it, and nothing has been submitted to the directory.

Results: **pass** means the item holds and names the test or file that satisfies it; **HELD** means the checklist's result for the item is "Held for a reviewer" and the plugin does the thing the row describes; **portal** means only the portal can confirm it, with what this repository does to prepare; **n/a** means the item does not apply because the plugin has no such component. A hold is not a block and not a rejection: the plugin can be submitted, and an Anthropic reviewer reads the held version before it goes live. No row of this pass reads "Blocks".

## The holds this pass expects

Three things about the plugin are held for a reviewer, by the checklist's own rules:

1. **The bundled fonts.** The board is one self-contained page, and `scripts/render-board.js` reads the four typefaces under `fonts/` to embed them in it, so every reader sees the same board with nothing fetched. The checklist holds a bundled font a script refers to. The fonts stay, and the hold is accepted.
2. **A hook's script that calls another file of the plugin.** `hooks/session-start.js` loads the plugin's own `scripts/lib.js`, and `hooks/show-result.js` runs the plugin's own `speak.js`, `render-board.js` and `render-record.js`. The checklist holds a call to another file in a script a hook runs. The calls stay, and the hold is accepted.
3. **The hooks are Node files.** The validator follows plain shell scripts only, and the three hooks are Node files started with `node`. The checklist holds a non-shell file a hook runs, whatever it does. This hold follows from what the plugin is.
