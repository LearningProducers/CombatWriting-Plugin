## Part 141 — The seat hook keeps its own record and opens no transcript (cw 0.9.20)

Issue 241. Part 140 measured that the fence cannot place a seat from the hook's own input, named the second road, a record of the hook's own, and left it for a ruling because it makes the hook a writer. The ruling came on 2026-11-21: build the record. This part builds it. The review's claim it answers: the seat hook read a file of the host's, the first record of the seat's transcript.

What is built:

1. The record. When the agent tool starts a seat, the call `hooks/seat-scope.js` already judges, the hook writes one file in the plugin's data folder, the folder the host names in `CLAUDE_PLUGIN_DATA`: `seat-scope/<session_id>/start-<time>-<pid>.json`, holding the seat's id, the run folder, the packet and the answer file as resolved paths, and the time. No text of the task, the draft or the brief is in it but what those paths carry: the task's two paths, resolved, and in them the run folder's own name, which the commands make from the first words of the draft, or of the brief when a run starts from the brief alone (the script, handed no name, uses the draft's file name, or the brief's when no draft is given). The file is its owner's alone to read.
2. The binding. A seat's own call carries its agent id and no task (Part 140's measurement). A seat with no record of its own that reads the packet, or reads or writes the answer file, of a start still waiting in its session takes that start, which becomes its record, `agent-<agent_id>.json`, and every later call of that seat is judged by it. A call that names any other file is refused and binds nothing. One rename takes the start, so two seats cannot take one; the seat's record is then created and never replaced, so a seat that has one never takes a second, two calls of its own at once included. A call that lands while another call of the same seat is taking a start waits for the seat's record, looking every 10 ms until half a second has passed, then once more, and is judged by it: a seat that reads its packet and its answer file in one turn is allowed both.
3. What the first call is trusted on. A seat with no record takes whichever waiting start of its session its call names, so until it is placed the hook trusts the seat to name its own. Until a seat has been allowed a call it has read no packet: it has read the plugin's agent file, the host's task and what the host hands every agent it starts. The trust that stood before stands: the host's task names the packet. What is new is that the seat's own first call picks the record, where the transcript's first line did. The task is the host's writing: a seat sent back is started with the checker's reason in its task, and a reason is the checker's own words and the numbers it measured, with no word of the answer that failed (Part 142; when this part was built a reason could quote the first 80 characters of that answer's first line).
4. No transcript. The hook's code no longer reads `transcript_path` and names no transcript. A start is still judged as it was (the two task lines, the packet inside a run's rounds folder, the answer file inside the run, the seat's record in `seats.json`).
5. A record by another hand is no record. A file of the hook's name that is a link, is not JSON, names a packet that is not a seat's packet inside a run's rounds folder, an answer file outside that run, or a run folder that holds no `seats.json`, places no seat. A seat whose own record is damaged is refused and takes no start. A link is never a folder of the hook's: one standing where the folder of records or a session's folder should be is not written through or read through, and the start is refused with that reason.
6. The records end. At a later start of a seat, in any session, the hook removes a session's folder of records once 30 days have passed since the last start or first call in it, at most twenty folders at one start: its own record files, and the folder when nothing else is in it. Thirty days is the least a record stays; with no later start of a seat it stays. A session's folder that is a link is not entered, a record that is a link is left where it is, and a failure there never stops a start.
7. The live proof holds the record. `tests/seat_scope_live.js` reads the data folder the host handed the throwaway plugin and finds one record of the seat there, naming the run's packet and answer file, with no start left waiting; then it removes its own session's records and leaves the folder. Its dump hook records the agent id, the session id and the data folder beside each call.
