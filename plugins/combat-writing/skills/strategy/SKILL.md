Run the Strategy stage of Combat Writing on `$ARGUMENTS` (ruled 2026-10-13: every stage in the help has a command). Strategy is steps 1 to 3 of the method: the person writes the draft, then the context brief. This command stores both and reads nothing: no packet is built, no seat starts, no rating is given. The order of the stages is the person's choice (2026-10-14): strategy may come first, after a sparring or battle round, or not at all; sparring and battle start a run from a pasted draft on their own. The rules that hold across every command are in the `combat-writing` skill; read `${CLAUDE_PLUGIN_ROOT}/method/combat-writing.md` once per session.

## 1. Record the paste, then read the arguments

If `$ARGUMENTS` carries pasted text rather than only a path and options, write the whole of `$ARGUMENTS` first, unchanged, to `combat-writing/inbox/<slug>.paste.md` in the project (the folder created if missing; the slug from the first words of the draft, or of the brief when there is no draft). Parse only after that file exists, and cut the pieces from it: the draft to `combat-writing/inbox/<slug>.md`, the brief to `<slug>.brief.md`, the reader to `<slug>.reader.md`. The same cut as sparring's. Nothing the person pasted is dropped before it is on disk. Write it byte for byte: every line break and every blank line as pasted; never join lines or reflow a paragraph, because the seats read the draft as stored and a lost break changes what they judge.

THE PASTE RULE (issue 76, 2026-10-26; the same words in battle and sparring): the paste is cut by its words, in any order. A keyword line opens a block, and a block runs to the next keyword line or the end. The keywords: `brief:`, `brief <name>:` (a brief saved by name), `brief update:` (or `update brief:`, with an optional name), `reader:` (`prospect:`), `battle:`, `sparring:`, `draft:`, `fq:` (`question:`, `focus:`), `n:` (`nav:`), `sn:`, `sfq:`, a seat line (`seat-2:`), `run:`; they match in any case, with or without the space after the colon, and a dash or bullet before the keyword, a dash in place of its colon, and a lone dash closing the paste are dropped (`brief-`, `-battle:` and `-Sn:` all read as the keyword). The draft is the `battle:`, `sparring:` or `draft:` block when there is one; else the text before the first keyword line (the form of issue 65); else, after a `brief:` block, the text that reads as the draft (it opens with a greeting line, `Hi,` or `Dear <name>,`, or is addressed to a reader), cut there as the best guess, the result's Brief and Draft lines showing what was taken as each, so a wrong cut is visible at once. A stage keyword, `battle:` or `sparring:`, names the stage as well: its block is the next piece, a new run, never a revision (a draft pasted when the newest run holds a brief alone still joins that run), and that stage runs on it whatever command carried the paste, said in one line ("Battle, as the paste says."); `draft:` keeps its meaning, a revised draft of the current run. Nobody is held to a keyword on the draft: the words make the cut certain, and the order is the person's.

- The draft: a file path, or pasted text, found by THE PASTE RULE above (a `draft:` block; else everything that is not a `brief:` block or a `brief update:` line; else the text after the brief that reads as the draft). A `battle:` or `sparring:` block here is that stage's: store nothing separately and run that command on the whole paste, as the rule says. `draft:` may mark it when the brief comes first. The draft is the person's own writing (step 2): never write it, never edit it, never trim it. If the person asks you to write the draft, say step 2 asks for a draft written by the person, and wait for it.
- `brief:` followed by text, or `brief: <path>`, is the context brief (step 3: who you are, your purpose, what you are attempting, the stakes); `context:` means the same. A brief given as a path is read from where it is. The brief you type is the project's from then on (issue 72): `new-run.js` writes it to `combat-writing/brief.md`, served to every later run in the project that brings no brief, said once in the result. `brief update:` (or `update brief:`) followed by text adds to the brief: cut it to `<slug>.brief-update.md` and run `brief.js --update <that file>` before `new-run.js`, which appends one dated paragraph to the project's brief (the run made next copies it); show its line as printed. A brief line that is only `same` or `last`, or ends in `keep`, from an earlier version means the project's brief: cut nothing and pass no `--brief`. The seats judge by the brief as written: a rule it states is applied, and a format choice it does not state (where the link sits, whether the greeting names the reader, what the closer is) is judged as the seats read it, as a fault if a rule seems to cover it. Put every format rule the draft follows into the brief.
- Keywords match case-insensitively, with or without the space after the colon.
- A `question:` (or `fq:`, `focus:`) or a seat line (`seat-2:`) given here belongs to sparring. Keep it in the inbox cut (`<slug>.fq.md`, `<slug>.<seat>.question.md`), do not send it, and carry it in the Next line at the end so the person can run it with one keypress.
- `n:`, `sn:`, `sfq:`, `rerate` and `final` are battle terms; say so in one line and point at `/cw:battle`, which runs on the stored draft once it is there.
- Briefs by name (Part 86, 2026-10-31): one project, many briefs. `brief <name>: <text>` (`brief cold-email: ...`, `brief blog: ...`, `brief speech: ...`; the name one word, lower case letters, digits, dashes or underscores) saves the brief as `combat-writing/briefs/<name>.md` and makes it this run's: cut the text to `<slug>.brief.md` and pass `--brief <that file> --brief-name <name>` to `new-run.js`; the unnamed default, `combat-writing/brief.md`, is untouched. `brief: <name>` alone, one word that matches a saved name (`briefs.js --names` lists them), picks it for the run with no text: pass `--brief-name <name>` and no `--brief`; a word that matches no saved name is not a brief: say so in one line, listing the saved names, and ask for the text (`brief <word>: <text>` saves one). `brief: <text>` with no name keeps its meaning, the unnamed default. `brief update <name>: <text>` adds a dated line to that saved brief (`brief.js --update <file> --name <name>`); `brief update:` with no name on a run whose brief is named adds to that brief, else to the default. The record, the board and the short form name the brief ("Brief: cold-email"); `/cw:briefs` lists every brief with its first line and the runs on it.
- `reader:` (or `prospect:`) followed by text is the reader (Part 84, 2026-10-31): who this one piece is for, in the author's words (the person and their company, what their site says, the page the piece answers). Cut it to `<slug>.reader.md` and pass `--reader <that file>` to `new-run.js` when this paste starts the run, or to `add-draft.js --run <folder> --reader <that file>` (with `--file` when a draft comes too, alone when not) on a run already there; it is written into the run as `reader.md`, the newest standing, carried in every packet under its own heading after the brief so every seat judges by it, shown under the brief on the record and the board, and never written to `combat-writing/brief.md`. The two have two lifetimes: `brief:` is the standing rules of the project, carried by every run; `reader:` is who this one piece is for and travels with the run. A reader pasted with no keyword is a brief to the cut, so the keyword is what keeps the prospect out of the project's brief.
- Strategy starts a new run, with one exception: when the newest run under `combat-writing/runs/` has an empty `rounds/` and no `draft.md` (a run this command made from a brief alone), a draft given here joins that run through `add-draft.js --stage strategy`, which writes it as `draft.md`. Strategy takes no `run:`; a second strategy on a draft already stored makes a second run.

### Two messages, the bare command and the picker

A missing piece is never an error. The draft and the brief may arrive in one paste or in two messages:

- **A bare command** (no draft, no path, no brief): ask for the draft in one line, "Paste the draft, or give its path. /cw:help for the full guide.", stop, and run this command with the next message as the draft. Never create a run with nothing; never refuse.
- **A draft with no brief**: write the draft to the inbox. When the project holds `combat-writing/brief.md`, that brief serves: create the run with the draft alone, no `--no-brief`, and the short form's Brief line says the project's brief is the run's; ask for nothing. Otherwise ask for the brief in one line, "Now the context brief: who you are, your purpose, what you are attempting, the stakes. /cw:help for the full guide.", stop, and take the next message as the brief, written whole to `<slug>.brief.md` (nothing is cut from it). If the person says there is no brief, create the run with the draft alone and `--no-brief`, and say in the Next line that sparring will read it cold.
- **A brief with no draft** (`brief:` or `context:` with nothing else, or a paragraph the picker below ruled a brief): create the run from the brief alone at once (step 3 below, `new-run.js --brief` with no `--draft`), so the brief is kept, and say in the Next line that the draft joins this run when it is pasted into `/cw:strategy`, `/cw:sparring` or `/cw:battle`. Do not ask for the draft and hold the brief in the conversation: the run is the memory. A `brief update:` alone, with no draft and no `brief:`: run `brief.js --update <file>` first, then `new-run.js` with neither, which makes the run from the project's brief, update included (the next session's first act: "update brief: new prospect is ...").
- **Text that is not clearly the draft**: a single short paragraph that reads as a brief (it says who the writer is, the purpose, the stakes) with no `brief:` keyword. Open the picker with the AskUserQuestion tool, one stage, one keypress, no "Other": **Draft** (the text is the draft) or **Brief** (the text is the brief). Mark the best guess with "(best guess)" on its label without moving it: a paragraph about the writer and the stakes is Brief; anything addressed to a reader is Draft. The question ends with "/cw:help for the full guide." If Brief, store it as a run from the brief alone, as above.

A draft alone, as a path or a multi-paragraph paste, needs no picker: it is the draft, and the brief is asked for next.

## 2. Decide where you are running

Fresh readers if you can start a separate agent and run `node`; otherwise one seat, the host. See the skill. In the one-seat case there is no run folder: say the draft and the brief stay in this conversation and that sparring or battle will read them from here, then skip to step 4.

## 3. Create the run

With the draft and brief files from step 1 (or the paths the person gave):

```
node ${CLAUDE_PLUGIN_ROOT}/scripts/new-run.js --draft <draft file> --brief <brief file> [--brief-name <name>] [--reader <reader file>] --stage strategy --name "<slug>" [--no-brief] --model "<the model you know you are running, or omit>"
```

It prints the run folder, copies the draft to `draft.md` (the snapshot, never changed) and the brief to `brief.md`, seats one fresh reader, `seat-1`, and logs the stage that made the run and which brief it has, so the record and the board say the run started at strategy. The brief given is the project's from then on: the script writes it to `combat-writing/brief.md`, which every later run that brings no brief then carries (the short form says so once; the file rides with the project in git, as the vault does). `--brief` is left out when the project's brief serves (it exists and the person pasted none) and `--no-brief` is added only when the person said there is no brief; `--draft` is left out when the person gave a brief alone (the run then holds `brief.md` and no draft, and the next draft pasted into strategy, sparring or battle joins it). A draft that joins a brief-only run goes in with `add-draft.js --run <folder> --file <draft file> --stage strategy [--reader <reader file>]` instead, which writes `draft.md`; a `reader:` given alone on that run goes in with `add-draft.js --run <folder> --reader <reader file>`.

If the add-on is present (a `crew_list` tool from the `combat-writing-crew` server), call `crew_register` with the run folder now, so the crew line below names every seat; it adds no seat twice, and sparring calls it again harmlessly. Without the add-on's tools, the crew is the one fresh reader, one company's models: tell installed-but-down from absent with `claude plugin list` and record it with `crew-state.js --run <folder> --state down|absent` (the skill's three states), so the result names the state and the next command. Build no packet and start no seat: strategy reads nothing.

## 4. Render and show the result

```
node ${CLAUDE_PLUGIN_ROOT}/scripts/render-record.js --run <folder> --short
node ${CLAUDE_PLUGIN_ROOT}/scripts/render-board.js --run <folder>
```

Show what the first prints as it is: the crew line, the "No rounds yet" line, the Started-at line, the Draft line (its words, paragraphs and lines, counted by code, and under it the one-line warning when a draft of more than 60 words arrived as one line: the person then pastes it again with its breaks before any seat reads it) and the seat key. Then one line each for the run folder, the brief (that it is stored, or that there is none) and the reader when one came ("Reader: <its first words>; this run's own, never the project's brief"), and one line saying the seats judge by the brief as written, so a format rule the draft follows belongs in it. No critique, no verdict, no reading of the draft: the seats read it in sparring or battle, and you are not a seat. Point at `record.md` in the run folder.

End with one line, the Next line, and nothing after it (ruled 2026-10-13; strategy is the one result that closes with the text Next line, not the picker, and the seat key stands above it in the short form):

```
Next: /cw:sparring, bare, sends the stored draft and brief to every seat with no repaste; add question: <your focus question> to put one question to every seat. Or /cw:battle fq:, n:, sn: or sfq: to start with the discussion; a first battle round carries no other seat's answer.
```

When a question or seat line came with the paste, the Next line carries it ready to run: `Next: /cw:sparring question: <the question>`. When there is no brief, the Next line says `/cw:sparring cold`. When there is no draft yet, the Next line says: `Next: paste the draft into /cw:strategy, /cw:sparring or /cw:battle; it joins this run with the brief.`
